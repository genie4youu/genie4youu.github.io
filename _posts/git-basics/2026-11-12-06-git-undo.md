무를 수 있는 범위는 그 변경이 작업 폴더, 스테이징, 저장소 중 어디까지 갔는지로 정해진다. 출력은 연습 저장소에서 실행한 그대로이고, 해시는 따라 해도 다르게 나온다.

## 1. 상황별 명령

| 상황 | 명령 | 결과 |
| --- | --- | --- |
| 편집을 버린다 (`add` 전) | `git restore <파일>` | 수정이 사라진다. 되찾을 수 없다 |
| `add` 를 무른다 | `git restore --staged <파일>` | 스테이징에서만 내린다 |
| 마지막 커밋을 고친다 | `git commit --amend` | 새 커밋으로 바뀐다 |
| push 전 커밋을 무른다 | `git reset` | 브랜치를 뒤로 옮긴다 |
| push 한 커밋을 취소한다 | `git revert <커밋>` | 취소 커밋을 더한다 |
| 하던 일을 잠시 치운다 | `git stash push` | stash 목록에 넣는다 |
| 잃은 커밋을 찾는다 | `git reflog` | HEAD 가 거쳐 간 자리를 본다 |

## 2. `restore` — 커밋 전의 수정을 버린다

```text
$ printf 'motor_speed = 999\n' > config.txt
$ git status --short
 M config.txt
$ git restore config.txt
$ git status --short
$ cat config.txt
motor_speed = 150
```

옵션 없이 쓰면 작업 폴더를 스테이징 내용으로 되돌린다. `add` 전이면 마지막 커밋 내용이다. 이렇게 버린 수정은 커밋된 적이 없어 되찾을 수 없다. `add` 를 잘못했으면 `git restore --staged <파일>` 이다. 스테이징만 HEAD 내용으로 되돌리고 파일은 그대로 둔다.

## 3. `commit --amend` — 마지막 커밋을 바꿔 쓴다

```text
$ git log --oneline -1
acaee5b log.txt 추가
$ git commit --amend -m "log.txt 추가 (로그 레벨 기본값 2)"
$ git log --oneline -1
c604dcf log.txt 추가 (로그 레벨 기본값 2)
```

해시가 바뀌었다. 고친 것이 아니라 새 커밋으로 바꾼 것이다. 빠뜨린 파일을 `add` 한 뒤 `--amend` 하면 그 파일도 들어간다. push 한 커밋에 쓰면 원격의 이력과 어긋나므로 05편의 rebase 처럼 push 전에만 쓴다.

## 4. `reset` — 브랜치를 뒤로 옮긴다

Pro Git 7.7 은 `reset` 을 세 단계로 설명한다. HEAD 가 가리키는 브랜치를 옮기고(`--soft` 는 여기서 멈춘다), 스테이징을 맞추고(`--mixed`, 기본값), 작업 폴더까지 맞춘다(`--hard`). `c604dcf` 위에 임시 커밋 1(`a831d23`)과 2(`6962696`)를 만든 뒤 한 단계씩 실행한 결과다.

| 명령 | 결과 |
| --- | --- |
| `git reset --soft HEAD~1` | 브랜치가 `a831d23` 으로. 커밋 2 의 변경은 스테이징에 남는다 (`A  tmp2.txt`) |
| `git reset HEAD~1` | 브랜치가 `c604dcf` 로. 스테이징이 비고 두 파일은 작업 폴더에 `??` 로 남는다 |
| `git reset --hard HEAD` | 추적 중인 파일을 커밋 내용으로 덮는다. 추적하지 않는 `tmp1.txt`, `tmp2.txt` 는 남았다 |

`--hard` 는 커밋하지 않은 수정을 덮어쓴다. Pro Git 7.7 은 이것을 `reset` 을 위험하게 만드는 유일한 옵션이라고 부른다. 커밋은 남는다(7절). 추적하지 않는 파일을 지우는 `git clean` 은 되돌릴 수 없으니 `-n` 으로 먼저 본다(Pro Git 7.3).

마지막 두 커밋을 하나로 합치려면 `git reset --soft HEAD~2` 뒤에 `git commit` 한다. git-reset 문서는 이미 남에게 준 커밋은 이렇게 무르지 말라고 적는다.

## 5. `revert` — 공유한 커밋은 취소 커밋으로

```text
$ git revert --no-edit HEAD
[main a0d9ec0] Revert "log.txt 추가 (로그 레벨 기본값 2)"

$ git log --oneline -3
a0d9ec0 Revert "log.txt 추가 (로그 레벨 기본값 2)"
c604dcf log.txt 추가 (로그 레벨 기본값 2)
7480fcc 충돌 해결 — A안(150) 채택
```

`revert` 는 지정한 커밋의 변경을 거꾸로 적용한 새 커밋을 기록한다. `log.txt` 는 사라졌지만 추가와 취소가 둘 다 이력에 남으니 원격과 어긋나지 않는다. push 전이면 `reset`, push 뒤면 `revert` 다.

## 6. `stash` — 하던 일을 잠시 치운다

```text
$ printf 'motor_speed = 777\n' > config.txt
$ git stash push -m "속도 실험 중"
Saved working directory and index state On main: 속도 실험 중
$ git stash list
stash@{0}: On main: 속도 실험 중
$ git stash pop
Dropped refs/stash@{0} (687d251...)
$ cat config.txt
motor_speed = 777
```

`push` 는 수정을 저장하고 작업 폴더와 스테이징을 HEAD 로 되돌린다. `pop` 은 꺼내 적용한 뒤 목록에서 지우고, 충돌이 나면 목록에 남긴다. 새 파일까지 치우려면 `-u` 를 붙인다(Pro Git 7.3).

## 7. `reflog` — 커밋한 것은 되찾는다

```text
$ git reflog -8
a0d9ec0 HEAD@{0}: reset: moving to HEAD
a0d9ec0 HEAD@{1}: revert: Revert "log.txt 추가 (로그 레벨 기본값 2)"
c604dcf HEAD@{2}: reset: moving to HEAD
c604dcf HEAD@{3}: reset: moving to HEAD~1
a831d23 HEAD@{4}: reset: moving to HEAD~1
6962696 HEAD@{5}: commit: 임시 커밋 2
a831d23 HEAD@{6}: commit: 임시 커밋 1
c604dcf HEAD@{7}: commit (amend): log.txt 추가 (로그 레벨 기본값 2)
```

`reset` 으로 뺀 `6962696` 이 `HEAD@{5}` 에 있다. 그 해시를 가리키는 브랜치를 만들면 돌아온다(Pro Git 10.7): `git branch recover 6962696`. reflog 마저 없으면 `git fsck --full` 로 dangling commit 을 찾는다.

reflog 에는 기한이 있다. 항목은 기본 90일(`gc.reflogExpire`), 지금 브랜치 끝에서 닿지 않는 커밋의 항목은 기본 30일(`gc.reflogExpireUnreachable`) 뒤에 정리 대상이 된다. `reset` 으로 뺀 커밋은 뒤쪽이니 미루지 않고 찾는다.

## 8. 정리 — 에이전트에게 맡길 때도 같다

- 커밋한 것은 되찾고 커밋하지 않은 것은 되찾지 못한다(Pro Git 2.4). 자주 커밋하고 나중에 `reset --soft` 로 합친다
- 에이전트가 만든 커밋은 push 전이면 `git reset --hard <그 전 커밋>` 으로 되돌리고, 잘못 되돌려도 reflog 에서 찾는다
- `restore`, `reset --hard`, `clean` 앞에서는 커밋되어 있는지부터 본다
- push 한 커밋은 `revert` 로만 무른다. 무를 수 있는 범위가 이 PC 안에 머물도록 push 와 `--force` 는 사람이 한다
