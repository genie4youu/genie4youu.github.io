## 1. 프레임이 길어서 시작 비트 하나로는 부족하다

[시리얼 02편](/posts/02-uart-baud-error-budget/)에서 UART 는 매 바이트인 10비트마다 시작 비트로 재정렬한다고 했다. 그래서 ±2% 오차를 견딘다. CAN 은 다르다.

| | UART | CAN |
| --- | --- | --- |
| 동기 기회 | 바이트마다, 곧 10비트마다 | 프레임 시작 1회에 프레임 중 엣지마다 |
| 프레임 길이 | 10비트 | 최대 130비트 이상 |
| 한 번의 동기로 버텨야 하는 길이 | 10비트 | 그냥이면 130비트다 |

130비트를 한 번의 동기로 버티려면 오차가 0.4% 이하여야 한다. 그것만으로는 부족해서 CAN 은 프레임 도중에도 계속 재동기화한다.

## 2. 두 가지 동기

하드 동기화는 SOF 의 하강 엣지, 곧 recessive 에서 dominant 로 가는 지점에서 무조건 비트 타이밍을 리셋한다. 프레임당 한 번이고 UART 의 시작 비트와 같은 역할이다.

재동기화는 프레임 도중 recessive 에서 dominant 로 가는 엣지를 볼 때마다 조금씩 보정한다. 엣지가 Sync_Seg 안에 있으면 완벽하다. 엣지가 Sync_Seg 보다 늦거나 이르면 위상 오차 $e$ 가 있는 것이고 그만큼 보정한다.

| 위상 오차 | 보정 |
| --- | --- |
| $e > 0$ 이라 엣지가 늦으면 내 시계가 빠른 것이다 | Phase_Seg1 을 $\min(e, \text{SJW})$ 만큼 늘려 샘플을 뒤로 민다 |
| $e < 0$ 이라 엣지가 이르면 내 시계가 느린 것이다 | Phase_Seg2 를 $\min(\lvert e\rvert, \text{SJW})$ 만큼 줄여 다음 비트를 앞당긴다 |
| $e = 0$ | 아무것도 하지 않는다 |

SJW(Synchronization Jump Width)가 한 번에 보정할 수 있는 최대량이다.

$$\text{SJW} \leq \min(\text{Phase Seg1},\ \text{Phase Seg2},\ 4\ \text{TQ})$$

한 번에 다 고치지 않고 SJW 로 제한하는 이유는 엣지가 노이즈일 수도 있기 때문이다. 글리치 하나에 타이밍을 크게 틀어버리면 그 뒤 비트를 전부 잘못 읽는다. 조금씩 여러 번 보정하는 게 안전하다. 진짜 클럭 차이라면 엣지가 계속 나오니 결국 따라잡는다. 노이즈였다면 영향이 SJW 만큼으로 제한된다.

제어 이론의 관측기 대역폭과 같은 맞교환이다. 빠르게 따라가면 노이즈에 민감하고 느리게 따라가면 진짜 변화를 놓친다. ADRC 의 $\omega_o$ 와 정확히 같은 성격의 문제다.

## 3. 엣지는 비트 스터핑이 만든다

재동기화를 하려면 엣지가 있어야 한다. 그런데 `000000` 이 이어지면 엣지가 없다. [기초 05편](/posts/05-basics-sync-async/)에서 본 비트 스터핑이 이걸 보장한다. 같은 값이 5비트 연속되면 반대 값 1비트를 강제로 삽입하므로 최소 6비트마다 엣지가 보장된다.

비트 스터핑의 역할을 이제 다 봤다. 재동기 기회를 보장하고, Stuff Error 를 검출하게 하고, Error Frame 이 그 규칙을 어겨 오류를 퍼뜨리게 한다. 하나의 규칙이 세 가지 일을 한다.

## 4. 클럭 오차 한계는 두 부등식으로 정해진다

Bosch 규격 §8.6 이 오실레이터 허용 오차 $df$ 를 두 조건으로 정한다. NBT 는 비트 시간의 총 TQ 수다.

$$df \leq \frac{\text{SJW}}{2 \times 10 \times \text{NBT}}$$

$$df \leq \frac{\min(\text{Phase Seg1},\ \text{Phase Seg2})}{2 \times (13 \times \text{NBT} - \text{Phase Seg2})}$$

둘 중 작은 값이 실제 한계다. 첫 식은 재동기화가 누적 오차를 따라잡을 수 있는지, 곧 10비트마다 SJW 로 보정 가능한지를 보장한다. 둘째 식은 엣지가 없는 최장 구간을 버티는지를 보장한다. 13비트는 프레임 끝에서 CRC delimiter 와 ACK 와 ACK delimiter 와 EOF 와 IFS 부근에서 엣지가 안 나올 수 있는 최대 길이다.

[05편](/posts/05-can-bit-timing/) 예제로 계산하면 NBT 가 16 TQ 이고 Phase_Seg1 이 3, Phase_Seg2 가 2, SJW 가 2 다.

$$df \leq \frac{2}{2 \times 10 \times 16} = 0.625\%$$

$$df \leq \frac{\min(3, 2)}{2 \times (13 \times 16 - 2)} = \frac{2}{412} = 0.485\%$$

따라서 $df \leq 0.485\%$ 다. 각 노드가 이 안에 있어야 한다. 두 노드의 상대 오차가 아니라 각각의 절대 오차 기준이다.

| 발진자 | 정확도 | UART (±2%) | CAN (±0.485%) |
| --- | --- | --- | --- |
| 크리스탈 | ±20~50 ppm (0.005%) | 여유가 400배다 | 여유가 100배다 |
| 세라믹 발진자 | ±0.3~0.5% | 여유가 4배다 | 거의 딱이라 온도 여유가 없다 |
| 내부 RC | ±1~3% | 아슬아슬하다 | 불가능하다 |

CAN 에는 크리스탈이 사실상 필수다. 세라믹은 실온에서 겨우 통과해도 온도가 변하면 나간다. 온도가 오르면 CAN 오류가 는다는 게 발진자 문제의 전형적 증상이다. 시리얼에서 UART 를 두고 본 것과 같은 현상인데 CAN 은 허용치가 네 배 빡빡해서 훨씬 자주 만난다.

```cpp
// comm_core/bit_timing.hpp 에 추가한다
// Bosch CAN Spec §8.6 의 두 부등식이다
constexpr double max_clock_tolerance(const CanBitTiming& t) {
    const double nbt = t.total_tq();
    const double c1 = t.sjw / (2.0 * 10.0 * nbt);
    const double c2 = std::min(t.phase_seg1, t.phase_seg2)
                    / (2.0 * (13.0 * nbt - t.phase_seg2));
    return std::min(c1, c2);
}

// 발진자 사양과 대조한다. 여기서 빌드가 막히면 부품을 바꿔야 한다
inline constexpr double kOscillatorTolerance = 50e-6;   // 크리스탈 ±50 ppm
static_assert(kOscillatorTolerance < max_clock_tolerance(k500k),
              "발진자 정확도가 CAN 비트 타이밍 요구를 못 맞춘다");
```

## 5. 여유를 늘리려면

둘째 식을 보면 Phase_Seg1 과 Phase_Seg2 중 작은 값이 클수록 좋다. 그런데 Prop_Seg 와 경쟁한다.

| 조치 | 효과 | 대가 |
| --- | --- | --- |
| 샘플 포인트를 87.5% 에서 75% 로 낮춘다 | Phase_Seg2 가 커져 여유가 는다 | 버스 길이가 제한된다 |
| 총 TQ 를 16 에서 20 으로 늘린다 | 세그먼트를 세밀하게 나눌 수 있다 | BRP 가 작아져야 하고 클럭이 충분히 빨라야 한다 |
| 비트레이트를 낮춘다 | 모든 게 여유로워진다 | 대역폭을 잃는다 |
| 버스를 짧게 한다 | Prop_Seg 를 줄여 Phase 에 배분한다 | 배치 제약이 생긴다 |
| 크리스탈을 쓴다 | 근본 해결이다 | 부품비 몇백 원이다 |

대부분의 경우 마지막이 정답이다. 크리스탈 하나로 이 절의 고민이 전부 사라진다.

## 6. 동기화 문제의 증상

| 증상 | 원인 |
| --- | --- |
| 온도가 오르면 오류가 증가한다 | 발진자다. 세라믹이나 RC 를 의심한다 |
| Stuff Error 가 많다 | 재동기가 못 따라간다. SJW 가 부족하거나 클럭 오차다 |
| 특정 노드만 오류를 낸다 | 그 노드의 발진자나 타이밍 설정 문제다 |
| 긴 8바이트 프레임만 실패하고 짧은 건 성공한다 | 누적 오차다. 클럭 여유 부족의 전형이다 |
| 버스를 늘리면 실패한다 | Prop_Seg 문제다 |

긴 프레임만 실패한다는 게 이 글의 대표 증상이다. 프레임이 길수록 재동기 기회는 있어도 누적 오차가 커지기 때문이다. 짧은 프레임으로 테스트하면 통과해서 원인을 못 찾는 일이 흔하다. 테스트는 반드시 8바이트 프레임으로 하고 `0x00` 이나 `0xFF` 처럼 스터핑이 많이 들어가는 데이터로 한다.

## 정리

- CAN 프레임은 최대 130비트 이상이라 시작 동기 한 번으로는 버티지 못한다.
- 두 가지 동기가 있다. 하드 동기화는 SOF 하강 엣지에서 프레임당 1회이고 재동기화는 프레임 중 엣지마다 한다.
- 재동기화는 $e>0$ 이면 Phase_Seg1 을 늘리고 $e<0$ 이면 Phase_Seg2 를 줄인다. 한 번에 최대 SJW 만큼이다.
- SJW 로 제한하는 이유는 엣지가 노이즈일 수 있어서다. 조금씩 여러 번이 안전하다.
- 이건 관측기 대역폭과 같은 맞교환이다. 빠르면 노이즈에 민감하고 느리면 놓친다.
- 비트 스터핑이 최소 6비트마다 엣지를 보장한다. 하나의 규칙이 재동기와 오류검출과 오류전파 세 가지를 한다.
- 규격의 두 부등식은 SJW 기준과 13비트 무엣지 구간 기준이고 둘 중 작은 값을 쓴다.
- 16 TQ 에 Phase1 이 3, Phase2 가 2, SJW 가 2 인 설정은 허용 오차가 0.485% 다.
- CAN 에는 크리스탈이 사실상 필수다. 세라믹은 온도 여유가 없고 내부 RC 는 불가능하다.
- 온도가 오르면 오류가 는다는 건 발진자 문제이고 긴 프레임만 실패하는 건 클럭 누적 오차다.
- 테스트는 8바이트에 스터핑 많은 데이터로 한다. 짧은 프레임으로는 문제가 드러나지 않는다.
