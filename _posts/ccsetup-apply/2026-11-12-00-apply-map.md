앞 구간은 각 갈래가 왜 필요하고 무엇을 하는지 다뤘다. 이 구간은 파일을 어디에 두고, 켜졌는지 무엇으로 확인하고, 어떻게 되돌리는지를 다룬다. 갈래는 앞 구간의 다섯에 Plugin 과 앱설정을 더해 일곱이다.

## 1. 어느 갈래인가

| 이런 상황이면 | 갈래 |
| --- | --- |
| 길고 매번 같은 절차를 Claude 가 상황을 보고 알아서 꺼내 썼으면 한다 | [Skill](/posts/01-apply-skill/) |
| 그 절차를 내가 정한 시점에 `/이름 인자` 로 부르고 싶다 | [슬래시 명령](/posts/06-apply-slash-command/) |
| Claude 가 바깥 프로그램이나 서비스를 도구로 써야 한다 | [MCP](/posts/03-apply-mcp/) |
| 남이 묶어 둔 skill, hook, MCP 꾸러미를 한 번에 받고 싶다 | [Plugin](/posts/02-apply-plugin/) |
| Claude 가 무엇을 판단하든 반드시 돌거나 반드시 막혀야 한다 | [Hook](/posts/04-apply-hook/) |
| 탐색이나 검토를 별도 컨텍스트와 좁은 도구로 떼어 내고 싶다 | [서브에이전트](/posts/05-apply-subagent/) |
| 확장은 그대로 두고 승인, 모델, 화면 동작을 바꾸고 싶다 | [앱설정](/posts/07-apply-settings/) |

갈래를 가르는 것은 누가 실행하느냐다. Skill 과 슬래시 명령은 Claude 가 읽고 따르는 글이고, Hook 은 Claude 가 skill 을 따르든 말든 Claude Code 가 이벤트마다 실행한다. 문서도 매번 지켜져야 하는 규칙을 skill 이 놓치면 hook 으로 옮기라고 한다. 「반드시」가 붙으면 Hook, 「보통은 이렇게」면 Skill 이다.

## 2. 적용표

| 갈래 | 언제 | 어디에 놓나 | 붙이는 순서 | 켜졌는지 확인 | 끄기와 되돌리기 |
| --- | --- | --- | --- | --- | --- |
| [Skill](/posts/01-apply-skill/) | 알아서 꺼낼 긴 절차 | `~/.claude/skills/<이름>/SKILL.md` (개인), `.claude/skills/<이름>/SKILL.md` (프로젝트) | 남의 것은 읽고 필요한 폴더만 복사 → description 다듬기 → 자동/수동 정하기 | `/skills`, description 속 말로 부탁해 보기 | 폴더 삭제, 설정의 `skillOverrides` 를 `"off"` |
| [Plugin](/posts/02-apply-plugin/) | 남이 묶은 꾸러미 | 범위별 설정 파일의 `enabledPlugins` (user, project, local) | marketplace 추가 → 상세 화면에서 추가될 것 확인 → 범위 골라 설치 → 안내가 나오면 `/reload-plugins` | `claude plugin list`, `/` 메뉴의 `/<plugin>:<skill>` | `claude plugin disable`, `claude plugin uninstall --scope <범위>` |
| [MCP](/posts/03-apply-mcp/) | 바깥 프로그램을 도구로 | local 과 user 는 `~/.claude.json`, project 는 `.mcp.json` | 신뢰 확인 → `claude mcp add --scope <범위>` → 비밀값은 환경변수 → `.mcp.json` 서버는 첫 사용 때 승인 | `claude mcp list` 의 `Connected`, `/mcp` 의 도구 수 | `/mcp` 에서 끄기(설정은 남음), `claude mcp remove <이름> --scope <범위>` |
| [Hook](/posts/04-apply-hook/) | 반드시 막거나 돌릴 때 | 범위별 `settings.json` 의 `hooks` 키 | 이벤트 → matcher → 명령 → 막으려면 `exit 2` 또는 JSON 의 `deny` | `/hooks` 목록, 걸릴 호출을 일부러 한 번 일으키기 | 항목 삭제, `"disableAllHooks": true` |
| [서브에이전트](/posts/05-apply-subagent/) | 별도 컨텍스트와 좁은 도구 | `.claude/agents/<이름>.md` (프로젝트), `~/.claude/agents/` (개인) | `name`, `description`, `tools` 를 적고 본문에 지시 | 이름으로 지명해 보기, `@` 멘션 | 파일 삭제, deny 규칙에 `Agent(이름)` |
| [슬래시 명령](/posts/06-apply-slash-command/) | 시점을 내가 정하는 절차 | `.claude/skills/<이름>/SKILL.md` (옛 `.claude/commands/<이름>.md` 도 동작) | 기본 명령과 안 겹칠 이름 → `argument-hint`, `disable-model-invocation: true` → 번호 단계 | `/` 메뉴, 시험 인자로 한 번 | 수동 전용으로 보관, 지울 때는 부르는 곳도 정리 |
| [앱설정](/posts/07-apply-settings/) | 확장 없이 동작 바꾸기 | `~/.claude/settings.json`, `.claude/settings.json`, `.claude/settings.local.json` | 범위 고르기 → 백업 → 키 한 곳만 수정 | `/status` 의 `Setting sources` 줄 | 키 삭제 또는 백업 복원 |

설정 파일은 대부분 저장하면 바로 반영되지만 `model`, `effortLevel` 은 세션 시작 때만 읽는다. 세션 중에는 `/model`, `/effort` 로 바꾼다.

## 3. 어느 갈래든 붙이기 전에

남이 만든 것을 붙일 때는 갈래와 상관없이 이것부터 묻는다.

| 질문 | 왜 |
| --- | --- |
| 무엇을 실행하나 | Skill 은 대부분 글이지만 Plugin, Hook, MCP 는 이 PC 에서 프로그램을 띄운다. 문서도 plugin 은 설치 전에 상세 화면을 읽고, MCP 서버는 신뢰하는지 확인하고 붙이라고 한다 |
| 어디까지 닿나 | 붙이는 순간 Claude 가 그 파일, 네트워크, 계정 범위를 쓴다. 비밀값은 설정 파일에 적지 않고 환경변수로 넘긴다. `.mcp.json` 은 `${VAR}` 를 펼쳐 준다 |
| 늘 컨텍스트를 먹나 | Skill 은 이름과 description 이 매 세션 목록에 실린다. 공식 marketplace 의 plugin 은 상세 화면에 매 턴 비용 추정치가 나온다 |
| 범위를 어디로 | 개인 전역, 프로젝트 공유, 프로젝트 개인. 시험은 좁게 시작하고 확인되면 넓힌다 |
| 끄는 법을 아나 | 각 편의 「끄기」 절. 끄는 법을 모르면 붙이지 않는다 |

범위가 겹칠 때의 우선순위는 갈래마다 다르다. 설정은 project local, shared project, user 순으로 이기지만 Skill 은 개인이 프로젝트를 이긴다.
