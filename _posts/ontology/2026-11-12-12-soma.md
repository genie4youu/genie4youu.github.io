SOMA(Socio-physical Model of Activities)는 일상 조작 작업을 하는 자율 로봇을 위한 OWL 온톨로지다. 브레멘 대학의 EASE 연구단이 만들고 DUL(DOLCE+DnS Ultralite) 위에 선다. SOMA 논문은 11편의 NEEM 을 「원시 센서 데이터, 구동기 제어 이력, 지각 이벤트를 SOMA 용어로 의미 주석한 로그」라고 정의한다. NEEM 서사에 쓰는 어휘가 SOMA 다.

## 1. 출발점 — 지식이 많으면 탐색이 줄어든다

논문은 Lenat 과 Feigenbaum 의 「more knowledge implies less search」로 시작한다. 토마토와 오레가노가 잘 어울리는 데에는 알고리즘적 이유가 없고 요리사는 그냥 안다. 자연어 명령 하나에 담긴 정보는 작업 수행에 필요한 정보보다 훨씬 적다. SOMA 는 세밀한 물리 맥락을 나열하는 대신, 행동의 기능이나 물체가 어떤 상황에서 맡는 역할 같은 사회적으로 구성된 지식을 함께 담으려 한다.

## 2. 물리 맥락과 사회 맥락

SOMA 는 온톨로지를 두 가지(branch)로 나눈다.

| 가지 | 담는 것 | 성격 |
| --- | --- | --- |
| 물리 (ground) | 물체, 행동 같은 물리 모델 | 물리 요소 자체 |
| 사회 (descriptive) | 역할, 작업 같은 사회 모델 | 마음에 의존한다. 물리 요소에 대한 개념이나 서술 |

논문의 예는 망치다. 망치는 어떤 맥락에서 흉기, 문진, 문버팀쇠로 개념화될 수 있다. 그래도 망치의 물리 분류(도구)는 바뀌지 않고, 다중 상속으로 망치를 문진의 하위 클래스로 만들지도 않는다. 역할은 DUL 의 `classifies` 관계로 물체에 붙는다.

DUL 을 고른 이유도 여기 있다. 논문은 IEEE ORA(10편의 CORA)가 기초 층으로 쓰는 SUMO 가 다른 모델에 비해 약하게 공리화돼 있다고 보고, 물리와 사회의 구분이 기초 층과 단단히 결합돼 있어야 한다고 설명한다.

## 3. 다섯 모듈

| 모듈 | 물리 쪽 | 사회 쪽 | 맡는 것 |
| --- | --- | --- | --- |
| ACT | Action | Plan | 에이전트가 수행한 사건과 그것을 구조화하는 계획 |
| PROC | Process | Progression | 운동처럼 진행 과정을 보는 사건 |
| STATE | State | Configuration | 물체끼리 접촉해 있는 것 같은 상태 |
| OBJ | Object, Disposition | Design, Affordance | 물체와 그 성질, 쓰임 |
| EXEC | Grounding | Binding | 작업 파라미터와 작업 사이의 연결 |

State 와 Process 의 구분은 시간 조각으로 정한다. 사건을 잘게 잘랐을 때 조각이 모두 같은 타입이면 State(homeomeric), 아니면 Process 다.

```mermaid
flowchart LR
    G["물리 맥락: 물체, 행동"] -->|해석| D["사회 맥락: 역할, 작업"]
    D -->|계획| G
```

논문은 계획을 사회 가지에서 물리 가지로 가는 대응(mapping)으로, 관찰한 사건의 해석을 그 반대 방향의 대응으로 본다.

## 4. 물체 — Role, Design, Disposition, Affordance

- **Role**: 「그는 학생이다」는 그 사람이 Student 클래스의 개체라는 뜻이 아니라 지금 학생 역할을 한다는 뜻이다. SOMA 는 프레임 의미론의 역할을 가져오고, `classifies` 에 제약을 걸어 어떤 역할은 물리 에이전트만, 어떤 역할은 특정 인공물만 맡게 한다.
- **Design**: 구조, 기능, 미적 패턴으로 물체를 묶는다. 목재 팔레트를 소파나 침대로 다시 쓰는 경우를 표현하고, 계획이 물체 타입 대신 기능을 가리키게 한다.
- **Disposition**: 물체가 affordance 를 실현하는 사건에 참여할 수 있게 하는 물체의 성질이다.
- **Affordance**: 여러 물체가 bearer, trigger, background 역할로 참여하는 관계적 맥락이다.

논문의 Manchester 문법 예:

```text
Class: LiquidContainmentDesign
    SubClassOf: FunctionalDesign,
        isDesignOf only (hasDisposition some
            (Containment and (affordsTrigger some (classifies only Liquid))))

Class: Cup
    SubClassOf: DesignedContainer,
        isDescribedBy some LiquidContainmentDesign
```

컵의 물리 분류(DesignedContainer)와 쓰임(액체 담기 설계)이 서로 다른 가지에 있다.

## 5. 추론 — 쓸 수 있는 것과 쓸 수 없는 것

로봇이 「액체를 담을 수 있는 것」을 찾을 때는 질의 개념을 정의한다.

```text
Class: WithAffordanceContainmentLiquid
    EquivalentTo: DesignedArtifact and (hasDisposition some
        (Containment and (affordsTrigger some (classifies only Liquid))))
```

포섭 질의로 아는 물체 중 이 개념에 속함이 증명되는 것을 고른다. 반대 질문 「액체를 담는 데 쓸 수 없는 것은?」에는 DesignedArtifact 의 하위 개념 C 마다 C 와 질의 개념의 교집합이 공집합인지 만족 가능성 검사를 한다. 공집합이 증명되면 그 클래스의 물체는 비싼 시뮬레이션으로 시험할 필요가 없다. 열린 세계에서 「아니다」를 말하려면 이렇게 공리로 증명해야 한다(06편).

## 6. 계획은 ABox 로 적는다

논문의 붓기 계획은 클래스 공리가 아니라 개체와 사실로 적혀 있다(요약).

```text
PouringPlan0  Plan        defines Pouring0, hasPhase Approaching0, hasPhase Tilting0
Pouring0      Task        usesRole Patient0, Source0, Destination0; startedBy Approaching0
Approaching0  MotionType  usesRole Destination1; overlapsWith Tilting0
Tilting0      MotionType  usesRole Patient1
Binding1      RoleBinding hasBinding Source0, Patient1
```

`Binding1` 은 붓는 출처와 기울이는 대상이 같은 물체라는 동일성 제약이다. 논문은 이런 동일성 제약을 OWL-DL 공리로 표현할 수 없어서 계획을 ABox 로 적는다고 설명한다. 대가는 OWL 추론기가 에이전트가 어떤 계획을 실행했는지 인식하지 못한다는 것이고, 논문은 작업을 수행하거나 그 실행을 인식하는 데 필요한 기제가 OWL-DL 의 범위 밖이라고 적는다.

| OWL 로 부족한 것 | SOMA 의 보완 |
| --- | --- |
| 순서 추론 | Allen 구간 관계를 끝점 그래프로 옮겨 점 기반 추론. pointisable 부분만 되고 논리합(disjunction)은 못 적는다 |
| 힘의 의미 | 당기기와 붙잡기는 접촉 패턴이 같다. Talmy 의 force dynamics(Agonist, Antagonist)로 구분 |
| affordance 시험 | 시뮬레이션 기반 추론 |

## 7. 규모와 관리

SOMA 1.1.0 은 논리 공리 1330개, 클래스 416개, 객체 속성 203개, 데이터 속성 38개이고 표현력은 SROIQ(D)다(FOIS 2021 논문 기준). 저장소에 커밋할 때마다 HermiT 추론기로 포섭과 분류 질의를 돌리고, Nothing 과 동치인 개념이 생기면 경고한다. 저장소 라이선스는 LGPL-3.0 이고, 사이트에서 SOMA.owl 과 SOMA-HOME.owl 을 받을 수 있다.

> 숫자는 1.1.0 기준이다. 최신판의 지표는 SOMA 사이트의 지표 절에서 확인한다.

## 8. 정리

- SOMA 는 물리 맥락(물체, 행동)과 사회 맥락(역할, 작업)을 나누고 `classifies` 로 잇는다. 다중 상속 대신 역할을 쓴다.
- 상위 온톨로지로 DUL 을 고른 이유는 이 구분이 기초 층과 결합돼 있어야 하기 때문이다.
- Disposition 과 Affordance 로 「무엇에 쓸 수 있나, 없나」를 포섭과 만족 가능성 검사로 답한다.
- 계획은 동일성 제약 때문에 ABox 로 적고, 순서와 힘과 시뮬레이션은 OWL 밖에서 보완한다.
