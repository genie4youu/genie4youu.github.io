Skill 을 언제 만드는지는 [07. Skill](/posts/07-skills/) 에서 다뤘다. 이 편은 어디에 두고, 어떻게 켜고, 무엇으로 확인하고 끄는지만 적는다.

## 1. 어디에 놓나

| 범위 | Claude Code | Codex |
| --- | --- | --- |
| 조직 | 관리 설정 폴더의 `.claude/skills/` | `/etc/codex/skills` |
| 개인 | `~/.claude/skills/<이름>/SKILL.md` | `~/.agents/skills/<이름>/` |
| 프로젝트 | `.claude/skills/<이름>/SKILL.md` | `.agents/skills/<이름>/` |
| plugin | `<plugin>/skills/<이름>/` → `/plugin이름:skill이름` | — |

Claude Code 는 이름이 겹치면 조직, 개인, 프로젝트 순으로 이기고, 프로젝트 skill 은 시작 폴더부터 저장소 루트까지 찾는다. Codex 는 같은 이름을 합치지 않고 둘 다 띄우며, `.claude/skills/` 는 읽지 않는다. 개인 범위의 description 은 모든 세션 목록에 실리니 한 저장소에서만 쓰면 프로젝트에 둔다.

## 2. 최소 예

```text
~/.claude/skills/build-log-errors/
├── SKILL.md            ← 켜질 때 본문이 실린다
├── reference.md        ← 필요할 때만 읽힌다
└── scripts/extract.py  ← 실행만 된다
```

```markdown
---
name: build-log-errors
description: 빌드 로그에서 오류와 경고만 골라 파일, 줄, 메시지 표로 정리한다. 빌드 실패, 컴파일 오류를 말할 때 쓴다.
allowed-tools: Bash(python ${CLAUDE_SKILL_DIR}/scripts/extract.py *)
---

1. 로그 경로를 받는다. 없으면 묻고 멈춘다.
2. `python ${CLAUDE_SKILL_DIR}/scripts/extract.py <로그>` 를 돌린다.
3. 결과를 표로 낸다. 형식이 낯설면 [reference.md](reference.md) 를 읽는다.
```

`${CLAUDE_SKILL_DIR}` 는 이 `SKILL.md` 의 폴더로 바뀐다. `allowed-tools` 는 이 skill 이 켜진 턴에 승인 없이 쓸 도구다. `name` 은 소문자, 숫자, 하이픈으로 폴더 이름과 같게 둔다.

## 3. 붙이는 순서

1. **남의 skill 이면 실행하기 전에 읽는다.** `hooks/`, `.mcp.json` 이 같이 있으면 plugin 구성이다. 받은 커밋을 적어 둔다.
2. **필요한 폴더만 복사한다.** 통째로 넣으면 description 이 전부 목록에 실린다.
3. **description 을 다듬는다.** 무엇을, 언제, 사람이 칠 말을 넣고 주된 용도를 맨 앞에 둔다. `when_to_use` 와 합쳐 1,536자에서 잘린다. 한국어로 일하면 한국어 트리거를 넣는다.
4. **자동과 수동을 정한다.** 아래 표.
5. **본문은 500줄 아래, 중요한 지시는 위에.** 압축 뒤에는 skill 마다 앞쪽 5,000 토큰만 다시 붙는다.
6. **Codex 와 같이 쓰려면** 공개 규격 여섯 필드(`name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools`)만 쓰고 같은 폴더를 `.agents/skills/` 에도 둔다.

| 머리말 | 내가 `/이름` | Claude 가 알아서 | 목록의 description |
| --- | --- | --- | --- |
| 기본 | 된다 | 된다 | 있다 |
| `disable-model-invocation: true` | 된다 | 안 된다 | 빠진다 |
| `user-invocable: false` | 메뉴에서 숨김 | 된다 | 있다 |

배포나 커밋처럼 부작용이 있는 절차는 수동 전용으로 둔다. 특정 파일에서만 켜려면 `paths:` 에 glob 을 적는다. Codex 의 수동 전용은 `agents/openai.yaml` 의 `policy.allow_implicit_invocation: false` 다.

## 4. 켜졌는지 확인

| 확인 | Claude Code | Codex |
| --- | --- | --- |
| 목록 | `/skills` | `/skills`, `$` 입력 |
| 직접 부르기 | `/이름 인자` | `$이름` |
| 알아서 켜지나 | description 속 말로 부탁하고 Skill 도구 호출을 본다 | 같다 |
| 머리말 파싱 | `claude --debug`, `claude plugin validate .claude/skills` (v2.1.233 이상) | — |
| 목록 비용 | `/context` 의 Skills 행, `/skill-doctor` | — |

편집은 세션 중에 바로 반영된다. 세션 시작 때 없던 최상위 skills 폴더만 `/reload-skills` 가 필요하다. Codex 는 안 보이면 재시작한다.

## 5. 끄기와 되돌리기

| 하고 싶은 것 | Claude Code | Codex |
| --- | --- | --- |
| 완전히 빼기 | 폴더 삭제 | 폴더 삭제 |
| 파일은 두고 끄기 | 설정의 `skillOverrides` 에 `"이름": "off"` | `~/.codex/config.toml` 의 `skills.config` 항목에 `name` 과 `enabled = false`, 재시작 |
| 자동 발동만 막기 | `disable-model-invocation: true` 또는 값 `"user-invocable-only"` | `policy.allow_implicit_invocation: false` |
| description 만 빼기 | 값 `"name-only"` | — |

`/skills` 에서 Space 로 바꾸고 Esc 를 누르면 `.claude/settings.local.json` 에 저장된다. deny 규칙 `Skill(이름)` 도 된다. plugin 의 skill 은 `skillOverrides` 로 꺼지지 않으니 plugin 째 끈다. 개인 skill 이 사라졌으면 `~/.claude/skills/.trash/` 부터 본다.

## 6. 자주 걸리는 것

| 증상 | 원인과 처방 |
| --- | --- |
| `/이름` 은 되는데 알아서 안 켜진다 | 머리말 YAML 이 깨지면 빈 머리말로 실린다. `--debug` 로 본다 |
| skill 이 늘자 일부가 안 켜진다 | 목록 예산(컨텍스트의 1%)을 넘으면 덜 쓰는 것의 description 부터 빠진다. 덜 중요한 것을 `"name-only"` 로 |
| 처음엔 따르다 나중엔 안 따른다 | 압축 뒤 앞부분만 남는다. 다시 부르고, 매번 지킬 규칙은 Hook 으로 |
| `allowed-tools` 로 다른 도구가 안 막힌다 | 미리 허용하는 목록이다. 빼려면 `disallowed-tools` |

이 PC 에서 겪은 것:

- 공개 skill 묶음 36개를 다 넣으면 목록의 description 이 약 6,550자, 필요한 10개만 고르면 약 2,593자였다. 필요한 폴더만 복사했다.
- 영어 원본 skill 이 한국어 요청에 켜지지 않았다. description 에 한국어 트리거를 덧붙인 뒤 켜졌다.
- 설치 명령(`npx skills add`)이 검토하지 않은 패키지를 하나 더 받아 실행했다. 검토한 clone 에서 복사한다.
