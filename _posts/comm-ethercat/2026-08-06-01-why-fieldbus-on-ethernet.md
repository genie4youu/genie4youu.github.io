## 1. 앞의 두 결론이 만나는 지점

이 연재의 앞부분이 두 개의 벽에 부딪혔다.

| 폴더 | 결론 |
| --- | --- |
| [CAN 10편](/posts/10-can-bandwidth-worst-case/) | 6축 1 kHz를 CAN 1 Mbps로 하면 부하율 162%. 물리적으로 불가능 |
| [CAN 12편](/posts/12-canopen-sdo-pdo/) | CANopen SYNC의 동기 오차가 수십에서 수백 µs |
| [이더넷 04편](/posts/04-why-ethernet-not-realtime/) | 표준 이더넷은 최악 지연의 상한이 없다 (최악 11 ms) |

필요한 것은 명확했다. 다축의 데이터를 한 사이클에 다 나르는 대역폭, µs급 동기, 계산 가능한 최악 지연. 그리고 이왕이면 이더넷의 성숙한 물리계층(100BASE-TX, 트랜스포머 절연, 100 m)을 재사용하고 싶었다.

## 2. 세 가지 접근과 EtherCAT의 선택

이더넷 04편에서 산업계의 네 해법을 봤다.

| 접근 | 발상 | 대표 |
| --- | --- | --- |
| ① 우선순위 | 급한 것을 먼저 | PROFINET RT |
| ② 시간 슬롯 | 언제 보낼지 미리 정한다 | PROFINET IRT, TSN |
| ③ 매체 접근 통제 | 마스터가 순서대로 폴링 | Powerlink |
| ④ 프레임 처리 방식 | 프레임을 하나만 쓴다 | EtherCAT, SERCOS III |

①②③이 공유하는 전제가 있다. **슬레이브마다 프레임이 하나씩 필요하다.** 그래서 N개의 프레임을 어떻게 배치할지를 푼다. 우선순위든 시간 슬롯이든 폴링이든.

EtherCAT는 그 전제를 뒤집었다. **프레임이 하나면 배치할 게 없다.**

프레임 하나에 모든 슬레이브의 데이터가 들어 있고, 각 슬레이브는 그 프레임이 자기를 지나가는 동안 자기 자리를 읽고 쓴다. 마지막 슬레이브에서 프레임이 되돌아 마스터로 온다.

이걸 on-the-fly 처리라 하고, EtherCAT의 나머지 전부가 이 하나를 성립시키기 위한 장치다.

## 3. 무엇이 달라지나

6축 로봇, 축당 입력 8바이트와 출력 8바이트, 1 kHz 기준이다.

### CAN 1 Mbps

$$12\ \text{프레임} \times 135\,\mu s = 1620\,\mu s \quad \rightarrow \quad \text{부하율 162\%}$$

### 표준 이더넷 + UDP (축당 프레임 하나씩)

$$12\ \text{프레임} \times 6.72\,\mu s = 80.6\,\mu s$$

대역폭은 여유롭다. 그런데 이더넷 04편의 최악 지연 11 ms와 지터가 문제다. 그리고 동시성이 없다. 12개 프레임이 서로 다른 시각에 도착한다.

### EtherCAT

프레임 하나에 6축 입력 48바이트와 출력 48바이트를 담는다.

| 항목 | 바이트 |
| --- | --- |
| 이더넷 헤더 + 프리앰블 + FCS + IFG | 38 |
| EtherCAT 헤더 | 2 |
| Datagram 헤더(LRW) + WKC | 12 |
| 프로세스 데이터 (6축 × 16 B) | 96 |
| 합계 | 148 |

$$t = \frac{148 \times 8}{100\ \text{Mbps}} = 11.8\ \mu s$$

여기에 슬레이브 통과 지연(슬레이브당 약 0.5 µs)과 케이블 왕복을 더해도 수십 µs다. 1 ms 주기의 2~3%이고, 프레임이 하나라 모든 축의 데이터가 같은 프레임에 있다.

축을 12개로 늘리면 프로세스 데이터가 192바이트가 되어 프레임이 244바이트, 19.5 µs다. 선형으로 조금 늘 뿐 프레임 개수는 그대로다. [기초 02편](/posts/02-basics-layers-osi-fieldbus/)에서 계산한 "슬레이브가 늘수록 효율이 좋아진다" 가 이것이다.

## 4. 그래서 무엇을 포기했나

공짜는 없다. 대가를 명확히 알아야 언제 쓸지 판단할 수 있다.

| 포기한 것 | 무슨 뜻인가 |
| --- | --- |
| 일반 이더넷 장비 호환 | 스위치를 못 쓴다. 일반 NIC가 `0x88A4` 프레임을 버린다 |
| 토폴로지 자유도 | 슬레이브를 정해진 순서로 이어야 한다 |
| 멀티마스터 | 마스터는 하나. CAN의 멀티마스터와 정반대 |
| 전용 슬레이브 하드웨어 | 슬레이브에 ESC(EtherCAT Slave Controller) 칩이 필요하다 |
| 라우팅 | 다른 망으로 못 나간다 |
| 동적 구성 | 슬레이브를 꽂았다 뺐다 하면 재설정이 필요하다 |

슬레이브에 전용 칩이 필요하다는 것이 가장 근본적인 대가다. 프레임이 선로를 지나가는 그 순간에 데이터를 읽고 쓰고 WKC를 올려야 하는데, 100 Mbps에서 한 비트가 10 ns다. 소프트웨어로는 절대 불가능하고 전용 하드웨어(ASIC 또는 FPGA)만 할 수 있다.

그래서 "우리 보드에 EtherCAT를 붙이자" 는 소프트웨어 결정이 아니라 하드웨어 결정이다. ESC 칩이나 IP 코어를 회로에 넣어야 한다.

### 마스터는 반대다

| | 슬레이브 | 마스터 |
| --- | --- | --- |
| 필요한 것 | 전용 ESC 칩 | 표준 NIC 하나 |
| 왜 | 프레임을 흘러가며 처리해야 | 프레임을 만들고 보내기만 하면 된다 |

마스터가 표준 이더넷 NIC로 되는 게 EtherCAT의 큰 장점이다. PC 한 대와 SOEM 같은 오픈소스만 있으면 마스터가 된다. 전용 마스터 카드가 필요 없다. [이더넷 05편](/posts/05-socket-programming-basics/)의 raw 소켓이 그 통로다.

## 5. 계층으로 보면

기초 02편의 3계층 축약 구조가 그대로다.

| 계층 | 내용 | 편 |
| --- | --- | --- |
| 7 응용 | CoE(CANopen), SoE, FoE, EoE, AoE | 11 |
| 2 데이터링크 | EtherCAT 프레임, Datagram, WKC, FMMU, SyncManager, ESM, DC | 04~09 |
| 1 물리 | 100BASE-TX (이더넷 그대로) 또는 EBUS | 03 |

3·4·5·6 계층은 없다. IP도 TCP도 쓰지 않는다.

1계층은 이더넷을 그대로 물려받고, 2계층을 완전히 다시 만들고, 7계층은 CANopen을 재사용했다. CAN 폴더에서 배운 CANopen이 여기서 재사용된다. CoE(CANopen over EtherCAT)가 객체 사전, SDO, PDO 매핑, CiA 402를 그대로 쓴다. 헛수고가 아니었다.

## 6. 언제 EtherCAT를 쓰나

| 상황 | 판단 |
| --- | --- |
| 다축이 µs급으로 동기해야 | EtherCAT (또는 SERCOS III, TSN) |
| 축이 많고 주기가 짧다 (1 ms 이하) | EtherCAT |
| 축 1~2개, 주기 10 ms | CAN으로 충분 |
| 센서 네트워크, 이벤트 기반 | CAN이 더 적합 (방송, 멀티마스터) |
| 기존 장비가 CANopen | CAN 또는 게이트웨이 |
| 원격지나 인터넷 경유 | EtherCAT 불가, TCP/IP |
| 무선 | 불가 |

CAN과 EtherCAT는 경쟁이 아니라 역할 분담이다. 실제 로봇에서는 주 제어축은 EtherCAT, 주변 장치와 안전 신호와 센서는 CAN을 같이 쓰는 구성이 흔하다.

## 7. 이 폴더를 읽는 법

02편이 심장이고 나머지는 그 파생이다.

| on-the-fly를 하려면 필요한 것 | 그래서 생긴 것 | 편 |
| --- | --- | --- |
| 프레임 안에서 내 자리 찾기 | 주소 지정 + FMMU | 05·06 |
| 지나가는 순간에 메모리를 안전하게 | SyncManager | 07 |
| 다 처리됐는지 마스터가 알기 | WKC | 04 |
| 슬레이브들이 같은 순간에 움직이기 | 분산 클록(DC) | 09 |
| 설정 순서 강제 | ESM | 08 |

각 편을 읽을 때 "이게 on-the-fly를 위해 왜 필요한가" 를 물으면 전부 연결된다.

## 정리

- 필요했던 것 셋: 다축 대역폭, µs급 동기, 계산 가능한 최악 지연. 그리고 이더넷 물리계층 재사용
- 우선순위, 시간 슬롯, 폴링은 전부 "N개의 프레임을 어떻게 배치할까" 를 푼다
- EtherCAT는 "프레임이 하나면 배치할 게 없다" 로 뒤집었다
- 6축 1 kHz에서 CAN은 부하율 162%로 불가능하고 EtherCAT는 프레임 하나 11.8 µs다. 축을 늘려도 프레임 개수는 그대로다
- 대가: 일반 장비 호환 불가, 토폴로지 제약, 마스터 하나, 슬레이브에 전용 ESC 칩 필요
- ESC 칩이 필요하다는 것은 EtherCAT 도입이 하드웨어 결정이라는 뜻이다
- 마스터는 표준 NIC 하나면 된다. PC와 SOEM으로 충분하다
- 계층: 1계층 이더넷 그대로, 2계층 완전 재작성, 7계층 CANopen 재사용
- CAN과 EtherCAT는 역할 분담이다. 주 제어축은 EtherCAT, 센서와 안전은 CAN
